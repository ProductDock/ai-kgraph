# REVIEW.md — PR review passes

Read by `.github/workflows/claude-review.yml` when someone comments `@review` on a
pull request (playbook Stage 5, [lesson 10](https://academy.claude.com/courses/ai-native-sdlc-playbook/ai-in-the-pr-review-loop)).
This defines what the review checks, how findings are ranked, and what it skips —
not how it's triggered; see [docs/pr-review-automation.md](docs/pr-review-automation.md)
for that.

## Passes

Run both project skills against the diff:

1. **`nextjs-code-review`** — Server/Client Component boundaries, Server Actions,
   caching and revalidation, metadata, route handlers, middleware, performance.
2. **`security-review`** — injection, XSS, authN/authZ, cryptography, and this repo's
   own rules: `process.env` only in `src/lib/env.ts`, `serverEnv` never reaching the
   client, no secret ever logged or echoed into a PR comment.

Also check against this repo's `CLAUDE.md` directory rules and state-management table
directly (component placement, query-key construction, `'use client'` boundary,
per-request `QueryClient`) — these are project conventions, not covered by either
skill's general Next.js knowledge.

## Severity

- **Important** — will break at runtime, is exploitable, violates a `CLAUDE.md` rule
  enforced nowhere else, or crosses a Server/Client boundary incorrectly.
- **Nit** — style, naming, a simplification that doesn't change behavior. Cap at **5
  nits per review**; past that, summarize the pattern once instead of repeating it per
  occurrence.

Findings are advisory. They never approve or block a PR by themselves — branch
protection and a human code-owner review remain the actual merge gate.

## Exclusions

- `components/ui/**` — generated by shadcn; review the calling code in
  `components/common/**` instead, not the generated primitives.
- Lockfiles, build output, anything under `.next/`.
- `intent/**` — reviewed through the intent/spec/plan gates, not this one.

## Separation of duties

The reviewing session must not push commits that resolve its own findings without a
human re-requesting it explicitly on that thread. Fixing and re-approving is one
person's job; writing the finding is another's, even when both are nominally "Claude".
